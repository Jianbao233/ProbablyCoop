# 内容 Mod 联机适配指南

ProbablyCoop 让两端运行各自的原版界面。房主验证并提交会影响共享店铺的操作。动画、悬停、指针、窗口开合和编辑草稿留在本地。共享物品用会话内实体编号定位，房间重建后会分配新的身份。

## 选择接入路径

| 内容类型 | 适配方式 |
| --- | --- |
| 物品、库存与容器 | 两端注册相同的物品定义与资源。沿用原版 `GameItem`、库存格、插槽和有效性查询。拖放由房主以当前实体、数量和位置验证。 |
| 图标与状态显示 | 优先用两端都有的原版图集和控件。复制明确的值，例如液位、标签和槽位。客机通过原版界面显示自己的投影。 |
| 自定义窗口或按钮 | 用可投影的原版控件组成窗口。已支持的 `AdvButtonElement` 可显示；自定义回调需要经显式业务命令接入后才能修改共享状态。 |
| 机器、事件、任务、交易 | 提交实体和预期状态等业务参数，房主验证后执行原版回调。随机结果、奖励、现金、库存与进度由同一处确认。 |
| 角色与存档 | 主动操作使用操作者自己的角色，健康和随身物品按角色隔离。共享存档由房主在原版保存边界写入。 |

对照现有实现时，可从以下入口追踪一次操作。

1. 看 [NativeContainerDrop.cs](../Game/NativeContainerDrop.cs) 如何把物品上的松手交给通用的插入、叠放和使用规则。
2. 看 [NativeWorld.cs](../Game/NativeWorld.cs) 和 [NativeHandAuthority.cs](../Game/NativeHandAuthority.cs) 如何验证命令、角色上下文、当前实体和持物请求。
3. 看 [NativeMirrorProbe.cs](../Game/Architecture/NativeMirrorProbe.cs) 与 [NativeMirrorLayouts.cs](../Game/Architecture/NativeMirrorLayouts.cs) 如何捕获共享事实并用原版控件恢复。这里的布局类型和 JSON 字段属于内部实现，可能随游戏更新变动。

当前适配入口是原版接口和 ProbablyCoop 的源码贡献流程。第三方 Mod 可以通过独立的内容定义接入已有路径。需要共享新动作时，请提交能复现的最小内容 Mod，或在 ProbablyCoop 中提出一个有明确校验和执行边界的适配。未经接入的任意委托、反射调用和鼠标点击没有通用的远程执行入口。

## 最小回归

1. 用两个相同构建的客户端和全新合作档，双方分别建房一次。确认客机能从初始快照进入，并打开与主机相同的原版控件。
2. 分别在两端拿放、使用和移动相关物品。同时操作不同物品，再尝试争用同一物品。核对两端看到的实体、数量、位置和归属。
3. 如果新增动作会花钱、生成物品或推进事件，验证重复提交、拒绝旧操作、退出重连，以及提交后读档。
4. 提交复现说明时提供游戏构建、Mod 清单、角色、场景、步骤及最小日志。隐去房间码、IP、Steam 账号、电脑路径和私人存档内容。
